BThree shape and density directions

The same Agents page built from the same components, changing only radius, control height, row height and spacing. Colours, type sizes and the shell are fixed.

Variant A

As built in the mock-ups, lifted to the 12px floor

Recommended

Idea

Keep the shapes the eight approved pages already draw: 8px controls, 12px cards, 9px tiles, pill chips, 32px controls and 32px table rows. Change only what the type rule forces: every label at 12px or more, sentence case, no tracking.

Pros

  • Every approved page already looks like this, so no screen has to be redrawn.
  • 32px rows sit inside the 28-32px band the live sheet settled on (styles.css:4436) and leave room for a two-line agent cell.
  • Pill chips and pill states read as different objects from square buttons.

Risks

  • Lifting 10px labels to 12px makes chips and heads about 15% wider; the densest capacity tables lose a column at 1280px.
  • Three radii (8, 9, 12) are close enough that someone will round them to one.
Variant B

Denser: 28px controls, 28px rows, square chips

Idea

Pull everything toward the live sheet's compact register: 6px controls, 8px cards, 4px square chips, 28px rows, 8px gaps, 8px tracks.

Pros

  • About 15% more rows per screen than A, which matters on Capacity and Workflows.
  • Closest to today's live radius (--ctl-radius-sm 6px), so the CSS change is smallest.

Risks

  • Square chips look like buttons; the state pill and a filter chip blur together.
  • 28px buttons are below a comfortable pointer target and need a separate phone size.
  • Departs from all eight approved mock-ups.
Variant C

Softer: pill controls, 16px cards, 40px rows

Idea

A calmer, consumer-style console: fully round buttons and inputs, 16px cards, 14px body, 40px rows and more air between regions.

Pros

  • Easiest to read for occasional users and on a phone.
  • One shape language (round) for every control.

Risks

  • A third fewer rows than A: an operator scanning 200 agents scrolls much more.
  • Round inputs and round buttons are hard to tell apart.
  • Reads as a different product from the approved pages.

DRecommendation

Adopt Variant A, as built, lifted to the 12px floor

The eight approved pages already draw A, so choosing it costs no redraw and keeps the series consistent. Its 32px rows sit inside the 28-32px band the live console already settled on, and its pill chips keep states and filters visibly different from buttons, which B loses. C costs a third of the rows an operator scans. B's density is worth keeping as a later "compact tables" setting, not as the default shape.

Small choices made in the frames

  • Control boundaries at 3:1. Inputs, secondary buttons and checkboxes use a new border token (#7d8ea3 light, #5f7087 dark) instead of the mock-ups' #dde5ee hairline, which measures about 1.3:1. The dark value is the live --line (styles.css:65), chosen there for WCAG 1.4.11.
  • Radius scale 4 / 8 / 9 / 12 / 14 / 999. This replaces the live 6 / 10 / 14 and its literals. 8 and 12 come from the mock-ups.
  • Table heads in 12px sans, sentence case, replacing the mock-ups' 10px uppercase mono and the live 13px mono.
  • One disabled treatment: 45% opacity, with the reason shown next to the control.
  • The busy button spins. That is a second animation besides the live pulse; redesign-v2.md §5.5 reserves animation for live. The spinner stops under reduced motion.
  • Toasts only acknowledge the viewer's own action and go after 4s. Failures stay as banners. This keeps the reason the live app has no toasts (Shell.tsx:648).
  • Hatch means "not a measurement", as the live --ctl-hatch does (styles.css:4481). redesign-v2.md §5.5 proposed hatch for warn as well; here warn uses amber plus the triangle mark, so the hatch keeps one meaning.
  • Parked reasons in plain words ("provider quota", "credential missing"), with the reason code in the tooltip and the detail view. The three that need a person get the amber flag.
  • Bars at 6px with a 3px radius (the mock-ups drew 5px; the live track is 8px).
  • Phone controls grow to 36px; tables become stacked cards.

Not grounded, or not found

  • Use counts are className string hits; classes assembled in template literals (for example .wf-state, .tabs) may be in use even though no hit was found.
  • The toggle switch, the toast, the busy button and the tooltip have no precedent in the code or the mock-ups. They are new here.
  • The memory bullet's hatched 90-100% band follows redesign-v2.md §4 row 5; no shipped chart draws it yet.
  • The dark-theme contrast of the new border token was computed by hand (about 3.5:1 on the dark surface), not by the repo's contrast tests.
