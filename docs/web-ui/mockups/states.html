When the console cannot show the platform

Every state the Sky spine shell must draw when a read fails, is still reading, comes back empty, or is about to change something. One rule from fetch.ts runs through every one: a failed request is never shown as empty data, and a missing figure is a dash with a reason, never 0. Names, ids, counts and ages in the frames are example data.

CVariant A · Every state is a banner in the page

Variant A

Banner under the page head, data dimmed below it

Idea

One component for every page-level state: a banner directly under the page head, above whatever data the page still holds, which is dimmed. Fatal and non-fatal states differ only in colour and action. Nothing ever replaces the page.

Pros

  • The smallest change from today: it is the existing StaleBanner raised to a standard.
  • One place to look on every page.
  • Data stays visible during a short blip.

Risks

  • For a fatal state the dimmed data underneath is a lie of omission: after an expired session nothing below will ever refresh, yet it still looks like a dashboard.
  • On a page that has never read anything, the banner sits above six skeletons that never resolve.
  • Several regions failing at once still draw several panels below the banner.

DVariant B · The shell owns the connection, in a status line

Variant B

Status line above the panel's user footer; pages stay quiet

Idea

Connection health is a property of the app, not of a page, so the shell shows it once: a line above the user footer (and a dot on the spine avatar when the panel is collapsed). Pages show only their own data and its age; a failed region shows not read in place.

Pros

  • Pages stay calm; no banner competing with the content.
  • One state, one place, on every route, the way the dock already shows the read log.
  • Fits how the 20 rps budget actually works: per person, across every tab.

Risks

  • The panel is hidden when collapsed and on a phone, which is exactly where people look least.
  • Easy to miss: a 236px footer line beside a full page of dimmed rows.
  • A fatal state (session expired) still leaves a full page that looks like data.

EVariant C · Fatal states take over the page; everything else is a banner or a region

Variant C

Three tiers: takeover, banner, region

Recommended

Idea

Sort states by how far they reach (section B). Whole app (session expired, tenant unresolved, wrong domain or disabled tenant, unreachable before any read): the content area is replaced by one panel with the cause, the "says nothing about what is running" line and the one action. The nav stays usable. Page (degraded, 429, unreachable with older data, admin only, not found): one banner under the head, data dimmed. Region: the card or table shows its own mark in place. The panel status line from B stays as a small echo, so a collapsed rail still carries a dot.

Pros

  • Generalises what Overview already does for session expiry (Overview.tsx:173-185) to every page, which is what its comment asks for: "seven independently empty cards is the bug".
  • A fatal state cannot be mistaken for a dashboard, because the dashboard is gone.
  • Non-fatal states keep last-good data, as the stale rule requires.

Risks

  • Needs one app-level decision point: which kinds are fatal. That is a new shared list beside NEEDS_A_PERSON, and the two must not drift.
  • A takeover during a 10-second blip of unreachable would flash; it applies only when nothing has been read yet.
  • Three components instead of one.

FEvery state, drawn in the recommended system

Variant C applied to each state the brief names. Page-level states are drawn in the shell; region-level ones are drawn as the region alone.

1 · Signed out and session expired (IAP)

Signed out is never drawn: IAP serves Google sign-in before the console loads. Session expired is the case the console must catch, and it arrives as a 200 with HTML (fetch.ts:650-672).

Signed out

Not a console state. With no IAP cookie the load balancer redirects to accounts.google.com before index.html is served, so SwarmCloud never draws a signed-out screen. Signing out from the panel footer sends people there too.

Submitting while expired

Submit checks the content-type on the 201 path too (Submit.tsx:117-122), so an expired session never reports a submission that did not happen. In C, the form keeps what was typed and shows the takeover as a panel over the form, not in place of it, so the text is not lost.

2 · API unreachable

Two forms, decided by whether anything has been read yet (fetch.ts:604-608).

3 · Degraded (503 upstream_degraded)

A dependency of the API did not answer. Not fatal, retried with back-off; the stale rule keeps the last good data on screen.

4 · 429 refreshing paused, and a paused pool

The brief calls this "dispatch paused". In the code a 429 pauses this browser's reads (rate_limited, "Refreshing paused"); it does not pause dispatch. A paused pool is the state that stops dispatch, and it is drawn differently. Both are below.

5 · 503 tenant unresolved

The API could not resolve which team the caller belongs to (per-group membership checks; searchTransitiveGroups is not available here). Every tenant-scoped read fails together, so it is a whole-app state; it is retried, because it can clear on its own.

6 · 403 admin only

Shown, never hidden: Admin carries a lock on the spine and in the panel. The page says nothing is wrong, in blue, not red (Shell.tsx:700-718).

7 · Loading: skeletons, never spinners

Skeletons keep the shape the data will take, and each card keeps its title. The page head says "Reading…". A spinner is used nowhere; a busy button says what it is doing.

8 · Empty, by kind

Three different facts, so three different panels. Each is a real zero from a successful read, says so with the solid mark, and keeps a ticking "Checked" line.

9 · One region failed, the rest of the page works

A region failure is drawn in the region, with its own mark and retry. The page head counts the reads honestly instead of claiming the page is fresh.

10 · Not found

The API returns the same 404 for an id that does not exist and for another tenant's id, so the page cannot and does not say which.

11 · After an action: inline, beside the control

Today there are no toasts, by decision (Shell.tsx:646-650). Confirmation is written where the action was taken, and states what the API recorded, read back, not what was asked.

12 · Typed confirm for destructive actions

Pool limits already asks for the pool name on a drastic cut (to 0, or by half or more; AdminSettings.tsx:306-317). Cancel workflow today is a two-click inline confirm with no typing; a typed confirm there would be new.

13 · Offline, stale and a hidden tab

A hidden tab reads nothing (Shell.tsx:380-401). Today nothing says so; the ages keep growing and the dimming starts at 5 minutes. Proposed below: say it on return, and tell a browser that is offline apart from an API that is down.

14 · The interface crashed

Not in the brief, but it is the one app-wide state left. It already exists (ErrorBoundary.tsx:33-52) and is a takeover in every variant.

GRecommendation

Variant C: takeover for whole-app states, banner for page states, marks in place for regions

A state that fails every read is a different fact from one that fails one read, and the code already treats it that way in one place: Overview replaces itself on an expired session because "seven independently empty cards is the bug". C makes that the rule for every page, keeps the stale rule (older data dimmed under a banner) for everything that can clear on its own, and keeps B's status line as a small echo so a collapsed rail still shows a dot.

Small choices made in the frames

  • Whole-app tier: session expired, tenant unresolved, wrong domain, tenant disabled, and unreachable before any read. Unreachable with older data is a page banner.
  • The takeover replaces the content area only. Spine, panel and Submit stay usable, so people can move between pages.
  • Tenant unresolved is amber, not red: it is retried with back-off and usually clears.
  • The panel meter and tenant block show "not read" and a dash during a whole-app state, never 0.
  • One banner per page, however many reads failed; the banner carries the count ("6 of 8 reads").
  • A 429 shows a countdown and no button, kept from today.
  • Confirmations stay inline. The toast is drawn for comparison only.
  • Proposed additions: a "this tab was hidden, reading now" line; an offline banner from navigator.onLine; a typed confirm on cancel workflow only while a step is running.

Found while reading the code

  • fetch.ts:113-115 classes an unrecognised 403 as admin_required, but the comment directly above it says "Do NOT guess -- guessing picks a gate page". The comment and the code disagree.
  • Submit.tsx:141 and SubmitWorkflow.tsx:147 map every 503 to upstream_degraded, so a submit during a tenant-resolution failure is reported as a degraded service. fetch.ts:121-136 tells the two apart; the submit paths do not.
  • The brief's "429 dispatch paused" does not match the code: a 429 pauses this browser's reads. A paused pool is what stops dispatch. Section F.4 draws both.
