Proposal B: Status cards

BGD asked on 2026-10-23 for complete, competing mock-ups of every new and changed page before anything is built (#2157). This is proposal B. Config opens on a page of status cards, and every page then shows its health before its lists. All data here is example data: the person is Operator, and the hosts are swarm.example.com and app.example.com.

The frames are drawn with the console's own tokens (apps/swarm-ui/src/styles.css) on the picked V2 Sky spine (navigation.html). Each surface is drawn at 1440 wide, which scrolls sideways inside its own frame, and at 390 wide as a phone. The toggle at the top of this page switches every frame between light and dark. The same three-way toggle is drawn in each panel's user footer, and it works there too. Rules from PICKS.md hold on every frame: nothing is smaller than 12px, there are no all-caps and no letter-spacing, and an unknown figure is a dash with its reason, never 0.

Idea

Every page answers "is this working?" before "what is in it?". Config opens on status cards: GitHub connected, N repositories reachable, secrets set or missing per scope, setup progress, MCP servers and people. Each card names its one problem, if it has one, and leads to its page. Each page then opens with a row of health tiles before its lists. Secrets is a card per scope, each with counts, and missing items are flagged on the card. Every value is set through a one-time form in a modal. Admin opens the same way, and Platform counts' Over time leads with big headline figures, then the chart, then the breakdown.

Pros

  • A workspace admin sees what is broken from one screen, without opening six pages.
  • The panel carries the same marks as the cards (for example "2 missing" on Secrets), so a problem is visible from any page in Config.
  • Health tiles are one component used on every page, so the pages stay consistent when they are built.
  • The phone reads well: tiles go two across, and lists become stacked rows.

Risks

  • Each landing reads more than one route, so the overview needs a summary route per card (or it reads slowly). The figures must stay honest while those reads are in flight: a dash with "reading…", never 0.
  • "At a glance" adds an entry to the Config and Admin panels. It is the section's landing page, not a seventh Config page.
  • Tiles take vertical space above every list. A person who visits only to find one row scrolls past them every time.
  • "Missing" needs a definition per item. Here it means a consumer that needs a value which is not set, never a guess.

    Example data throughout. No value on this page is a credential: a set secret is drawn as its name and its state, never its characters.
