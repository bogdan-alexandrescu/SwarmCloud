Proposal D: Heatmap and composition

A dense operations view of the new Over time section of Admin › Platform counts. A matrix heatmap shows how many agents ran in each bucket, for each agent type, model, workspace or pool account, at a glance. Beside it (beneath it in a window narrower than 1,440), composition bars split the tokens into their four kinds and a waterfall builds the estimated cost key by key. The live state counts stay at the top of the page as they are today.

Example data only: user Operator, workspaces eng, smoke and u-operator, the viewer in America/New_York, now Fri Oct 23 2026 at 00:41. Every bucket is folded from one daily example, so a week, a month and a breakdown add up to each other. Use the theme toggle above (or in the panel's user footer of any frame) to see both themes.

Idea

One matrix answers "when, and who". Buckets run across. Down the side are either the five measures, each on its own scale (no breakdown), or the breakdown's keys on one shared scale, shaded by the measure you pick. Beside it, or beneath it below a 1,064px content area, two composition charts answer "of what". Tokens are a 100% bar of input, output, cache read and cache write per key. Cost is a waterfall that steps from key to key to the total, with the stopped-run estimate drawn outlined inside it and an unreported remainder drawn as an open dashed stub. A coloured cell never carries a number. Figures live in the readout, the row totals and the card heads.

Pros

  • Density: 26 weeks × 6 accounts in 620px, and an outlier week or a dead account shows without reading a digit.
  • Magnitude is one hue, light to dark, so the series palette's weakest pair never meets in the matrix.
  • Every honesty mark is a shape, not a colour (hatch, outlined 0, plain cell, notch, dashed stub), so it survives greyscale and print.
  • The waterfall shows where the money went and how much of it is an estimate. The token bar shows that cache reads dominate, which no line chart of totals shows.
  • On a phone the matrix turns instead of scrolling sideways.

Risks

  • A heatmap shows order, not value: five bins hide small differences, and an exact figure needs a hover or a tap. The readout and row totals carry the figures. The build would add the ledger's per-cell names and one tab stop with arrow keys (charts/README.md).
  • With no breakdown, each row has its own scale. Comparing two rows' shades means nothing, and the legend has to say so every time.
  • Token kinds need four series hues. Measured with the dataviz validator: --series-2 is under the chroma floor (0.099), and series 1 and 2 side by side are ΔE 14.1 at normal vision (the floor is 15). The order input · output · cache read · cache write (series 1, 4, 3, 2) keeps every neighbouring pair at ΔE 21.3 or more at normal vision and 12.9 or more for deutan. The legend table names every kind.
  • Cache read is about 85% of tokens, so output and cache write are slivers. Their figures are in the table, not the bar.
  • Stopped-run estimates are about 1% of cost and are drawn at least 3px wide, which slightly overstates them.
  • At a 16px pitch, the 12px floor allows a date label only every fourth week.

F1The page before Run

Nothing over time is read until Run is pressed. The section keeps its shape and says what pressing will read and roughly what it costs; no empty chart, no zero.

F2After Run: week buckets, no breakdown

With no breakdown the matrix's rows are the five measures: agents, retries, run hours, tokens and estimated cost, one row each and each on its own scale. One look shows where volume, rework, time and spend peaked, and whether they peaked together.

F3The same, broken down by agent type

Picking a breakdown turns the rows into its keys. Now every cell is one measure, shaded on one shared scale, picked with "Shade by" (agents by default). The composition column gains one row per key, in the matrix's order.

F4Month buckets, broken down by pool account

Twelve months from sealed days: the button priced it at about 1,130 reads before it was pressed. Twelve columns are wide enough to keep the matrix upright on a phone too.

F5Partial data, with every honesty mark on screen

A separate example from F2–F4, made to show every mark at once: day buckets over 30 days in which one day could not be read, codex agents reported no cost for three days, a few attempts reported no tokens, a Sunday had no agents at all, and today's agents have not ended.

F6Interaction: one bucket's readout, and picking a breakdown

Hover (or focus: the matrix is one tab stop, arrow keys move a cell) shows a readout with every figure the bucket has, each with its coverage. The row's key lights in both composition charts. Picking a breakdown re-prices Run; it never reads by itself.

F7Phone: how the charts reflow at 390

No horizontal page scroll at 390: every drawing on a phone is 342 wide or less, and labels follow the 12px floor by labelling every other row, never by shrinking. F2–F6 show agent type and pool account at 390; the two drawings here are the other two breakdowns, workspace and model, so all four are drawn somewhere on this page.
