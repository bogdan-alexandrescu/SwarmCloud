Proposal C: the repository is the hub

BGD asked on 2026-10-23 for complete, competing mock-ups of every new and changed page before anything is built (#2157). This is proposal C, Repository-centric. Config › Repositories is a list, and opening a repository shows everything about it on one page: who and what can reach it, its secrets for agents, QA sign-ins and GitHub Actions, its QA targets with their environments, and its index. Workspace and personal things keep their own pages. Every frame is drawn once and shown at 1440 and 390; the Theme control above (and the one in each frame's panel footer) switches every frame between light and dark. All data is example data: the user is Operator, the hosts are swarm.example.com and app.example.com, and no value of any secret appears anywhere.

    Idea

    Config holds six pages: GitHub access, Repositories, Secrets, MCP servers, People and roles (group workspaces, admins only) and Workspace settings. Repositories is the hub. A repository's page has five sections on one scroll, each with its own address: Overview, Access, Secrets (Agents | GitHub Actions), QA targets, Index. When a repository is open, the panel nests those sections under Repositories, so the spine and panel always say where you are. Secrets' own page has the scopes Workspace · Yours · Repository; its Repository scope is an index across repositories whose rows open each repository's Secrets section. A QA run group page hangs off its repository. Settings keeps Profile; Admin is drawn only for admins.

    Pros

    • One page answers "can agents work on this repository?": a failing push check, a missing QA sign-in, an Actions environment's branch rule and a stale index sit side by side.
    • It mirrors GitHub's own layout (repository › secrets › environments), so the Actions destination and "Create on GitHub ↗" read naturally.
    • Who may set a repository's secrets depends on the repository (a member GitHub calls its admin may), so the page says once, at the top of the section, what you may do here.
    • Cross-repository questions still have one answer: the Secrets › Repository index, and the Repositories list's filters.

    Risks

    • Two ways into a repository's secrets (the index and the repository page). The index only links; every Set happens on the repository page, so there is still one form.
    • A long page on a phone. Sections fold to their summary line, and the section strip scrolls sideways.
    • A name set for the workspace and for a repository lives on two pages; the override line has to be drawn on both, and is.
    • QA targets move under the repository their findings file in, so there is no single QA list; the Repositories list's "Has QA targets" filter stands in for it.
