AAgents: the split view

Decided on 2026-10-01: the list on the left, the selected agent on the right with Details, Attempts, Artifacts and Checkpoints as tabs, and a route per agent (/agents/<tab>/<id>). The owner picked the compact list, with the option to collapse it to a strip or drag it wider. Agents, costs and times are example data.

Variant 1

Compact list, wide detail, with a collapse toggle and a snapping divider

Owner's pick · 2026-10-01

Idea

The default is a 380px list of two-line rows (mark, name, elapsed; then profile, owner, try or the reason it waits) beside a detail pane with Details, Attempts, Artifacts and Checkpoints tabs. Step and Class move into the detail head. Search by name or pasted task id sits above the list (#99). A « button in the list header, or the [ key, collapses the list to a 64px strip of state marks with a hover card each; dragging the divider snaps to strip (64px), compact (380px) or wide (50%). The last choice is remembered in this browser (decided 2026-10-01); remembering it per person across devices is a later enhancement that needs a preference store on the API.

Pros

  • The list is readable at every width from 1024px up, and the selected row is always visible beside its detail.
  • Waiting rows carry their reason in the list itself, so PARKED and READY are told apart without opening anything.
  • One route per tab and per agent, so any view is a link.

Risks

  • The width is remembered per device only, in browser storage, until the API gets a per-person preference store (a later enhancement).
  • The list drops two columns (Step, Class) that some operators sort by. They come back in the detail head and in a "Group by workflow" toggle.
  • Below 1024px the split no longer fits and has to switch to the phone model.

BWhat exists today

Agents today, from Agents.tsx and agentlist.ts

  • Three tabs: Live (LEASED, DISPATCHED, STARTING, RUNNING), Waiting (READY, PARKED and the rest), Recent (SUCCEEDED, FAILED, CANCELLED, DEAD_LETTERED), each with a count from the loaded rows. It opens on the first tab with rows.
  • Recent has a state segment (all, failed, cancelled, succeeded). DEAD_LETTERED is deliberately not offered. A profile select and "Group by workflow" (not on Live) complete the bar.
  • Columns: State · Agent (profile, model, short id) · Owner · Step · Elapsed · Try · Class, plus a "why" line in warn ink when someone has to act.
  • One read, GET /v1/tasks?limit=200 (50 on a phone). It polls every 5s while Live has rows, else 30s, and pauses in a hidden tab.
  • A row opens the inspector drawer at #work/task/<id>; the open row is marked.

The inspector today, from AgentDetail.tsx, AttemptTimeline.tsx, Artifacts.tsx, RunFiles.tsx, CheckpointBrowser.tsx

  • A resizable drawer with three panes: Details, Attempts, Artifacts. Checkpoints live inside Details and open the checkpoint browser from a "files" button.
  • Details: headline (state, liveness, stop), facts (run, age, by, tenant, wf), six tiles (Elapsed, Attempts, Peak memory, Tokens, Token cost, Checkpoints), then attempts, dispatch, code, output, checkpoints, input, timeline. Polls every 10s until a terminal run settles.
  • Attempts: one card per attempt, "Attempt N · gen G", exit chip, OOM near miss, facts (att, ran, exit, rss, ckpt), the error and its events.
  • Artifacts: inputs, the answer, files (500-file cap, with the over-cap count), logs (transcript, stdout, stderr, runner).
  • Stop opens an inline confirm, "Stop this agent?", and calls POST /v1/tasks/{id}/cancel.
  • Open polish: #82 (Agents and inspector QA), #99 (find by pasted task id), #102 (one home per fact), #94 (name by workflow step), #179 (silent worker), #379 (which account), #109 (phone rows).

CDecided, and what it needs

Compact list by default, collapsible to a strip, with a divider that snaps

  • Three widths for the list: strip (64px), compact (380px, the default) and wide (50%). « or [ toggles strip and compact; the divider snaps to the nearest of the three; the choice is stored in this browser; a per-person store on the API is a later enhancement.
  • Routes: /agents/live, /agents/waiting, /agents/recent?state=failed; an agent is /agents/<tab>/<id> plus /attempts, /artifacts, /checkpoints. A link to an agent in another tab redirects to the tab its state belongs to.
  • The checkpoint browser becomes the Checkpoints tab, with the archive tree under the table. It is no longer a drawer inside a drawer.
  • Each waiting row states its reason in the list. Parked says when it resumes, ready names the full pool, and queued names what it waits on.
  • Polling stays as it is: the list every 5s while anything is live, the detail every 10s until a terminal run settles.
  • On a phone the list and the agent are two pages on the same routes, with a back link.
Alternatives considered: full table with a free divider, and a strip-only list
Variant 2

Full table, adjustable divider

Idea

The list stays today's table and the divider is draggable; columns drop from the right as the list narrows.

Pros

  • Nothing about the table changes for people who know it.
  • Wide screens can show both the full table and the detail.

Risks

  • Every width is a different set of columns, which is hard to test and hard to describe.
  • At 1280px the detail gets about half the width, which is tight for the attempt cards and the checkpoint tree.
Variant 3

List collapses to a strip

Idea

Opening an agent shrinks the list to a 64px column of state marks (like a mail client), giving the detail almost the full width. Hovering a mark shows the agent's name.

Pros

  • The detail has the most room of the three.
  • Moving between agents with the keyboard is still one keystroke.

Risks

  • A column of marks says nothing about which agent is which without hovering.
  • It brings back the "drawer covering the list" feeling the split view was meant to end.
