# Agent quality capability matrix

One row per capability, in the program's ten areas, read on main at
`3e3a9875458719f438df1c2d426ae1844b4122b3` ([baseline](baseline.md)). The four
columns are kept apart on purpose, because the program's rule is to keep
proposed, implemented, behaviourally tested, enabled in configuration and
live-verified apart:

* **Implemented**: the file and symbol on this commit. "Not implemented" when
  the tree has no code for it, with where it is proposed.
* **Behaviourally tested**: a test id that exercises the behaviour. A test that
  only reads a document or a file's text says so. `scripts/agent_quality_inventory.py`
  checks that every cited pytest id names a test function that exists, and every
  console test file exists; it cannot say the test ran or passed, which only a
  CI run says.
* **Enabled in configuration**: the file and key that switch it, with the
  default. "Always on" means no switch exists. A workspace setting's live value
  is in Firestore and is not read from here.
* **Live-verified**: only with a named record (a measured batch, a dated live QA
  run, a workflow id) that shows the capability working, or failing, on a
  deployment. Otherwise **not read from here**: unknown, never "no" and never
  "yes".

Paths are relative to the repository root; `agent_worker/` is
`apps/agent-worker/agent_worker/` and `swarm_api/` is
`apps/swarm-api/swarm_api/`.
